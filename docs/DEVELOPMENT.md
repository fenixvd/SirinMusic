# Разработка Sirin Music 2.0

Работа над следующей версией ведётся в `dev`. Стабильная ветка — `master`; изменения переносятся туда после проверки и решения о выпуске. Pull request следует направлять в `dev`.

## План версии 2.0

Главная задача — переработать Activity, экраны и навигацию приложения с единым оформлением Material 3 и адаптацией к компактным и большим экранам. Пункты ниже описывают план, а не уже готовые функции.

### Настройки приложения

Отделить настройки приложения от профиля пользователя. Собрать здесь тему, цвета из обоев, готовые палитры и свой цвет, размер и очистку кеша, ручную проверку обновлений и два независимых переключателя автоматической проверки. Проверки при запуске и в фоне должны оставаться выключенными по умолчанию.

### Профиль и радио

Добавить данные и действия, доступные на сервере musik:

- Состояние обучения вкуса, количество лайков и скипов, текущую долю новых треков и часто звучащих исполнителей.
- Нижнюю и верхнюю границы новизны радио с сохранением на сервере.
- Статистику радио за неделю: треки, дослушивания, скипы, исполнители и источники рекомендаций.
- Выбор нескольких настроений, отображение и изменение активных настроений.
- Список временно скрытых объектов и возврат последнего скрытого.
- Создание и просмотр ссылок на радио для других слушателей.

Перед реализацией проверить актуальные контракты API сервера. Все значения получать с сервера; примеры статистики не использовать как константы. Предусмотреть загрузку, ошибки, пустые состояния и отсутствие функций в старой версии сервера.

### Главный экран и навигация

Добавить действия «Запустить радио», «Поделиться» и «Обновить миксы». Пересмотреть переходы между экранами, расположение элементов и поведение на разных размерах окна. Для пунктов меню можно добавить смысловые иконки Material, сохранив текстовые подписи и доступность.

### Подключение

Сохранить и учесть вход по QR-коду из PR #1, уже добавленный в `dev`: сканирование внутри приложения и ссылки `musik://connect`. При QR без токена очищать прежний токен; ожидающее подключение должно сохраняться при пересоздании Activity.

Подготовить вход по логину и паролю после проверки серверного API: формат запросов, результат авторизации, срок жизни и обновление учётных данных. Новый способ входа пока запланирован; его контракт и окончательная структура экрана ещё не утверждены.

## Проверка изменений

```sh
./gradlew :app:testDebugUnitTest :app:lintDebug :app:assembleDebug
```

Проверять навигацию, пересоздание Activity, подключение, компактные и широкие экраны. Воспроизведение и системное управление проверять на устройстве. Изменения интерфейса не должны нарушать серверную очередь, оценки и защиту учётных данных.

## Тестовые сборки и публикация

Текущий CI проверяет `master` и `dev`. Debug APK доступен в артефакте `sirin-music-debug`; при push в `dev` дополнительно собирается оптимизированный APK с подписью приложения.

В workflow пока сохранены техническая версия `1.5-dev`, одноимённый старый тег и артефакт `sirin-music-1.5-dev`. Это существующая конфигурация CI, а не название текущего плана разработки. Обновление документации не меняет версии APK, теги или workflow. Тестовые артефакты не публикуются как GitHub Release и не предлагаются встроенной проверкой обновлений.

Версия 2.0 выпускается после завершения работ и проверки. Порядок подписи и публикации описан в [RELEASING.md](RELEASING.md).

## Уже реализованные механизмы

Следующие разделы описывают существующую реализацию, которую нужно сохранить при переработке экранов.

## Память и хранилище

Обложки используют ограниченный LRU-кеш: 64 МиБ на диске и до 24 МиБ в оперативной памяти (не более 10% доступной приложению heap). При уведомлении Android о нехватке памяти или уходе интерфейса в фон кеш в RAM очищается. Изображения, которые ещё отображаются на экране, могут оставаться в памяти до закрытия экрана.

В настройках показывается текущий размер дискового кеша и доступна кнопка очистки. Она удаляет кеш обложек в RAM и на диске; данные подключения, избранное на сервере и воспроизведение не затрагиваются. Отображаемые обложки могут кешироваться повторно при следующих запросах. Музыка на диск не сохраняется.

Размер «Приложение» в Android не равен размеру APK и не является размером кеша. Для release включены R8 и удаление неиспользуемых ресурсов. Размер установленных файлов и подготовленного Android кода зависит от устройства. Debug-сборки не уменьшаются R8.

## Оформление и большие экраны

Десять готовых палитр и свой цвет: оттенок, насыщенность, яркость или HEX. [MaterialKolor Color Utilities](https://github.com/jordond/MaterialKolor) строит полную светлую/тёмную схему с контрастным текстом. При включённых цветах из обоев используется системная схема; для выбора своего цвета этот переключатель нужно выключить.

На широких окнах используется навигационная панель сбоку, адаптивные сетки избранного, артистов, альбомов и плейлистов. В плеере от 840 dp управление и очередь располагаются в двух колонках с независимой прокруткой. Настройки, вход, профиль и тексты песен ограничены по ширине для удобного чтения.

## Оптимизация после первой dev-сборки

JSON декодируется в фоновом потоке. Поиск обрабатывает только открытую вкладку, с задержкой 200 мс при вводе; пустой запрос возвращает исходный список без копии. Сравнение текста не создаёт lowercase-копии метаданных каждого трека. Позиция воспроизведения больше не передаётся в библиотеку; оценки и доступность действий обновляются отдельно. Обложки в списках используют AsyncImage с общей подложкой вместо подкомпозиции. Завершённые фоновые задачи удаляются из реестра ViewModel, включая операции избранного с разными ID.

## Обновления приложения

В настройках есть кнопка «Проверить новую версию», открывающая отдельный экран обновлений и запускающая проверку по явному нажатию. Флажок «Проверять обновления при запуске приложения» по умолчанию выключен. При включении выполняется одна проверка за процесс приложения; возврат из фона, поворот и пересоздание Activity её не повторяют. Изменение флажка действует со следующего запуска процесса. Суточная проверка через WorkManager также по умолчанию выключена и включается отдельно. При выключенном переключателе периодическая задача отменяется; после включения первая фоновая проверка назначается через сутки. Оба механизма независимы, ручная проверка доступна при выключенных флажках. Разрешение Android на уведомления запрашивается отдельной кнопкой.

Клиент проверяет только стабильные GitHub Releases. Артефакты ветки `dev` и тег без Release не предлагаются; Сравнение учитывает числовые компоненты и prerelease. Загрузка начинается по кнопке, идёт потоково в один временный APK, ограничена 64 МиБ; проверяются размер, SHA-256 из метаданных GitHub, имя пакета, версия, совместимость Android и совпадение сертификатов установленного приложения. Системный установщик дополнительно проверяет APK и требует подтверждения пользователя. Debug-сборка не сможет обновиться APK с production-подписью.

Для установки используется FileProvider с доступом только к `cache/updates/`. Частичная загрузка удаляется при ошибке или отмене; завершённый APK хранится до установки или очистки устаревших файлов при запуске (сутки). Клиент GitHub отдельный и не содержит токен сервера musik.
