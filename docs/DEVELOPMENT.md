# Разработка Sirin Music

Разработка идёт в `dev`, стабильные выпуски — в `master`. Pull request принимаю в `dev`.

Версия в этой ветке — **2.0.2**, код `5`. Имя и код версии записаны в `app/build.gradle.kts`; локальная сборка и CI используют одни и те же значения.

## Сборка и проверки

Для Gradle нужен установленный JDK 21, для компиляции — JDK 17. Версии остальных инструментов указаны в [README](../README.md).

```sh
python3 -m unittest discover -s tools -p 'test_*.py'
./gradlew :app:testDebugUnitTest :app:lintDebug :app:assembleDebug
```

Кроме автоматических тестов, на устройстве проверяются навигация, восстановление экранов, подключение и воспроизведение. Для плеера важны работа в фоне, управление из уведомления и отключение наушников. Интерфейс рассчитан на компактные и широкие окна.

GitHub Actions проверяет `master` и `dev`. Debug APK находится в артефакте `sirin-music-debug`. После push в `dev` также собирается подписанный APK `SirinMusic-dev.apk` в артефакте `sirin-music-dev`. Встроенная проверка обновлений предлагает только стабильные GitHub Releases.

Выпуск описан в [RELEASING.md](RELEASING.md), сборка для F-Droid — в [../fdroid/README.md](../fdroid/README.md).

## Очередь и воспроизведение

Очередью управляет сервер musik. Для запуска используются серверные сессии трека, альбома, исполнителя, плейлиста или подборки. Избранное запускается через `/api/mixes/favorites/play` с выбранным `start_track_id`, поэтому кнопка следующего трека продолжает очередь избранного. Конец фиксированной очереди останавливает воспроизведение. Переход назад использует историю сессии.

Избранное и оценки радио разделены. Сердечко сохраняет запись, а «нравится» и «не нравится» обучают профиль рекомендаций. Дизлайк сам по себе не переключает трек.

ExoPlayer работает вместе с системной медиасессией. При отключении наушников музыка ставится на паузу. Пауза также отменяет отложенный запуск, который ещё ждёт ответа сервера. Нажатие на уведомление открывает экран текущего трека.

## Вход и учётные данные

Подключиться можно по QR, API-токену или имени и паролю. QR распознаётся локально через ZXing. Сканер поддерживает камеру, фонарик, выбор изображения и ручной ввод ссылки. Камера работает при открытом экране сканера; изображения декодируются с ограничением до 2048 пикселей.

Для входа по паролю используется `/api/auth/token`. В режиме аккаунтов передаются имя и пароль, в режиме одного владельца — пароль. Если сервер возвращает несколько профилей, пользователь выбирает профиль телефона. Пароль остаётся в памяти только на время входа. Для выбранного профиля сервер выпускает токен устройства.

Подключение проверяется через `/api/auth/me` и `/api/health`. Кнопка входа без токена доступна, когда сервер сообщает об отключённой авторизации. На сервере без `/api/auth/token` остаются QR и ручной токен.

Токен плеера хранится зашифрованно и исключён из резервных копий Android. Ссылки с токенами не записываются в состояние восстановления экранов.

## Аккаунты и устройства

Управление аккаунтом открывается отдельно и использует повторный вход по имени и паролю через HTTPS. `AccountApi` работает со своей cookie-сессией, отдельно от Bearer-токена плеера. Cookie ограничены адресом сервера, перенаправления запрещены, запросы изменений отправляют CSRF-токен.

Пароль и cookie не сохраняются на диск. Сеанс переживает поворот экрана через ViewModel и закрывается вместе с окном управления. Экран защищён `FLAG_SECURE`.

Доступны смена пароля, создание, переименование и удаление профилей, а также управление токенами устройств. Для администраторов есть приглашения и права пользователей. Удаление профиля, отзыв и перевыпуск токенов, изменение прав подтверждаются пользователем. Сервер дополнительно защищает основной профиль и последнего администратора.

Выбор профиля в окне управления относится к этому сеансу. Кнопка «Использовать профиль в приложении» отдельно переключает профиль плеера и получает новый токен. Старые токены при этом автоматически не отзываются.

Новые токены и ссылки приглашений видны сразу после создания. Они не восстанавливаются из `savedInstanceState`, а при копировании помечаются как чувствительные данные. QR создаётся локально в формате `musik://connect`.

## Радио, подборки и профиль

Главная позволяет запустить радио, отправить ссылку на него и обновить миксы. Обновление создаёт серверное задание `mix_pack`. Приложение ждёт его до трёх минут и затем перечитывает подборки. Для выполнения задания на сервере нужен работающий воркер; закрытие приложения не отменяет задание.

Данные профиля приходят из нескольких методов API:

| API | Данные |
| --- | --- |
| `/api/profile` | Оценки, границы новизны и частые артисты |
| `/api/metrics/weekly` | Статистика за неделю |
| `/api/metrics/recommendations` | Новизна последнего набора рекомендаций |

Если сервер не вернул показатель, приложение не подставляет выдуманное значение. Ошибка одного раздела не скрывает остальные данные.

Настроения хранятся на сервере и применяются к текущей сессии радио; одновременно можно включить несколько. Скрытые записи можно вернуть. Ссылки на радио можно создавать, отправлять через Android и отзывать; API-токен приложения в такую ссылку не входит.

## Синхронизация между устройствами

Плеер восстанавливает сессию через `/api/playback/state` и `/api/now` на паузе, без повторного события `track_start`. При запуске он запрашивает управление сессией, а во время воспроизведения сохраняет состояние каждые пять секунд. Если управление перешло другому устройству, телефон ставится на паузу.

Пауза и перемотка сохраняются отдельно. Постоянных запросов на паузе нет; при возвращении на экран приложение запрашивает актуальное состояние. Если сервер отвечает 404 для нового API состояния, синхронизация отключается до смены подключения. Сетевые ошибки обрабатываются отдельно. Сессия с изменившимся треком не восстанавливается под старым идентификатором.

## Изображения, память и поиск

Обложки используют общий LRU-кеш: до 64 МиБ на диске и до 24 МиБ в RAM, в пределах 10% памяти, доступной приложению. При нехватке памяти и уходе интерфейса в фон кеш RAM очищается. Изображения, которые ещё видны на экране, могут оставаться в памяти до закрытия экрана.

В настройках показан размер дискового кеша и есть кнопка очистки. Она очищает кеш изображений; подключение, серверное избранное и воспроизведение сохраняются. При следующих запросах кеш заполняется снова. Музыка на диск не загружается.

Фото артистов приходят через `/api/artist-photos` и используют тот же кеш. При ошибке или ответе 404 отображается обложка. Фотографии загружаются на сервер отдельно: само обновление musik их не добавляет.

JSON декодируется в фоновом потоке. Поиск обрабатывает открытую вкладку с задержкой 200 мс после ввода; пустой запрос возвращает исходный список. Списки библиотеки не получают обновления позиции плеера. Оценки и доступность действий обновляются отдельно, завершённые фоновые задачи удаляются из реестра ViewModel.

Release-сборка использует R8 и удаление неиспользуемых ресурсов. Размер приложения в настройках Android включает установленные и подготовленные системой файлы, поэтому отличается от размера APK и кеша.

## Оформление и широкие экраны

Есть десять готовых палитр и выбор собственного цвета по оттенку, насыщенности, яркости или HEX. [MaterialKolor](https://github.com/jordond/MaterialKolor) строит светлую и тёмную схемы. Цвета из обоев используют системную схему; собственная палитра доступна при выключенном переключателе цветов из обоев.

На широких окнах навигация перемещается на боковую панель, а списки используют адаптивные сетки. В плеере от 840 dp управление и очередь занимают две колонки с независимой прокруткой. Ширина текстов, форм входа, профиля и настроек ограничена для удобного чтения.

## Обновления

Кнопка «Проверить новую версию» открывает экран обновлений и запускает ручную проверку. Автоматические проверки при запуске и в фоне по умолчанию выключены и включаются независимо.

Проверка при запуске выполняется один раз за процесс. Поворот экрана и возврат из фона её не повторяют; изменение настройки действует со следующего запуска процесса. Фоновая проверка через WorkManager выполняется раз в сутки, первая — через сутки после включения. Выключение переключателя отменяет периодическую задачу. Разрешение на уведомления запрашивается отдельной кнопкой.

Updater обращается только к стабильным GitHub Releases. Он сравнивает версии, загружает APK по нажатию и проверяет размер, SHA-256 из метаданных GitHub, пакет, версию, совместимость Android и сертификат. Загрузка ограничена 64 МиБ и использует отдельный HTTP-клиент без токена musik. Debug-сборка подписана другим ключом и не обновляется стабильным APK поверх себя.

Для установки используется FileProvider с доступом к `cache/updates/`. Незавершённая загрузка удаляется при отмене или ошибке. Готовый файл хранится до установки либо очистки устаревших файлов при следующем запуске спустя сутки. Установку подтверждает пользователь в системном окне Android.

## Настройки сервера

Отдельный экран настроек сервера открывается из профиля и настроек приложения. Используются `/api/settings`, `/api/settings/dirs`, `/api/settings/external-ip` и `/api/settings/restart`. Выбор музыкальной папки относится к файловой системе сервера.

Режимы LAN и Интернет слушают все сетевые интерфейсы; доступ снаружи зависит от роутера или туннеля. Сохранение настроек не запускает сканирование музыки и не меняет подключение телефона. Перезапуск доступен при `restart_supported=true` и подтверждается пользователем. При ответе 403 для токена устройства приложение объясняет, как получить административный доступ через браузер.

Экран защищён `FLAG_SECURE`. Токен и QR остаются в памяти, а буфер обмена токена помечается как чувствительный. Внешний IP запрашивается по нажатию.

В Docker сохранение зависит от конфигурации контейнера и постоянного хранения `/app/.env`. Если API не может сохранить настройки или перезапустить сервер, интерфейс показывает соответствующее сообщение.
