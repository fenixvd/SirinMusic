# Выпуск Sirin Music

Релизы собирает и публикует workflow **Android Release** в GitHub Actions. Его запускает подписанный тег вида `v2.1.1`. Коммит с этим тегом находится в истории `master`.

## Версия

Имя и код версии хранятся в `app/build.gradle.kts`:

```kotlin
versionCode = 8
versionName = "2.1.1"
```

Для каждого нового выпуска код увеличивается. Например, у 2.0.1 код `4`, у 2.0.2 — `5`, у 2.1.0 — `6`, у 2.1.1 — `8`. Номер запуска GitHub Actions на версию не влияет.

Перед сборкой CI сверяет тег с исходниками:

```sh
python3 tools/release-version.py --tag v2.1.1
```

Если версии не совпали, задача останавливается до загрузки ключа подписи. Повторный запуск того же workflow использует ту же версию.

## Подпись APK

Sirin использует один сертификат для стабильных обновлений. Android проверяет его при установке, поэтому новый ключ не подходит для обновления уже установленного приложения. Ключ хранится вне репозитория; резервная копия хранится отдельно.

GPG-подпись Git-тега и подпись APK — разные подписи. Тег подписывает коммит выпуска, а сертификат APK позволяет Android проверить само приложение.

Для настройки собственной копии проекта ключ можно создать так:

```sh
keytool -genkeypair -v \
  -keystore /secure/path/sirin-release.jks \
  -alias sirin \
  -keyalg RSA -keysize 3072 -validity 10000
```

Пароли и данные сертификата `keytool` запрашивает в терминале.

## Секреты GitHub Actions

Workflow использует четыре секрета репозитория:

| Секрет | Значение |
| --- | --- |
| `SIRIN_KEYSTORE_BASE64` | Хранилище ключа в Base64 |
| `SIRIN_KEYSTORE_PASSWORD` | Пароль хранилища |
| `SIRIN_KEY_ALIAS` | Имя ключа |
| `SIRIN_KEY_PASSWORD` | Пароль ключа |

Хранилище можно передать без вывода его содержимого:

```sh
base64 -w 0 /secure/path/sirin-release.jks | gh secret set SIRIN_KEYSTORE_BASE64
```

Пароли добавляются через настройки Actions или интерактивную команду `gh secret set ИМЯ_СЕКРЕТА`. Во время сборки workflow восстанавливает ключ во временном каталоге и удаляет его после завершения, в том числе при ошибке.

## Локальная проверка

Подписанная сборка использует переменные `SIRIN_KEYSTORE_PATH`, `SIRIN_KEYSTORE_PASSWORD`, `SIRIN_KEY_ALIAS` и `SIRIN_KEY_PASSWORD`. Они задаются в окружении. Пароли не записываются в исходники и историю команд.

```sh
./gradlew :app:testDebugUnitTest :app:lintRelease :app:assembleRelease :app:bundleRelease
"$ANDROID_HOME/build-tools/37.0.0/apksigner" verify --verbose \
  app/build/outputs/apk/release/app-release.apk
```

Без переменных ключа release APK остаётся неподписанным. Debug APK использует отдельную подпись разработки.

Сборки из `dev` доступны в артефакте Actions `sirin-music-dev`. Стабильные обновления публикуются отдельно, по тегам.

## Публикация

После тестов и проверки на устройстве изменения из `dev` попадают в `master`. Выпуск запускается отправкой тега. Например, для 2.1.1:

```sh
git tag -s v2.1.1 -m 'Sirin Music 2.1.1'
git push origin master
git push origin v2.1.1
```

Дальше Actions выполняет тесты и lint, собирает APK, проверяет подпись и публикует APK вместе с `SHA256SUMS.txt` в GitHub Release.

Для Google Play AAB можно собрать локально задачей `:app:bundleRelease` с теми же переменными подписи. Файл появится в `app/build/outputs/bundle/release/app-release.aab`; он не добавляется в Git и GitHub Release. Сертификат ключа должен совпадать с сертификатом ключа загрузки приложения в Play Console. Код версии 2.1.1 — `8`; ранее загруженные версии должны иметь меньший код.

Обычный тег создаёт стабильный релиз. Тег с суффиксом, например `v2.1.1-rc.1`, создаёт предварительный релиз; суффикс также входит в `versionName` исходников. Workflow можно запустить вручную для уже существующего тега. Повторный запуск заменяет вложения этого релиза APK той же версии. Опубликованные теги сохраняют свой исходный коммит.

## F-Droid

Рецепт F-Droid использует ту же подпись APK. В рецепт сборки входит SHA-256 публичного сертификата, а приватный ключ остаётся у разработчика. Проверка независимой сборки описана в [../fdroid/README.md](../fdroid/README.md).
