# Настройка релизов

Основная ветка репозитория — `master`. Релиз собирается по тегу, коммит которого уже входит в историю этой ветки. Отправка тега запускает публикацию, если настроены секреты подписи.

## Подготовка версии 2.0

Версия 2.0 разрабатывается в `dev`; план переработки экранов и подключения описан в [DEVELOPMENT.md](DEVELOPMENT.md). Перед выпуском проверить изменения на устройстве, совместимость с API сервера и обновление поверх установленной стабильной версии. Затем перенести проверенные изменения в `master` и публиковать релиз по отдельному решению о выпуске.

Тестовые APK из `dev` доступны в артефактах CI. Текущая локальная тестовая версия — `2.0rc0.2-dev`; после push проверенных изменений CI создаст артефакт `sirin-music-2.0rc0.2-dev`. Выпуск тестового APK не создаёт тег или Release.

Команды ниже — примеры будущего выпуска 2.0.0, а не указание публиковать его сейчас. Использовать существующий ключ подписи APK и возрастающий `versionCode`.

## Ключ подписи APK

Используй отдельный ключ для релизов Android и сохрани его защищённую резервную копию. Для установки обновлений поверх существующего приложения Android требует тот же сертификат. GPG-подпись коммита и подпись APK — разные механизмы.

Создай хранилище ключей вне репозитория. `keytool` запросит пароль и данные сертификата:

```sh
keytool -genkeypair -v \
  -keystore /secure/path/sirin-release.jks \
  -alias sirin \
  -keyalg RSA -keysize 3072 -validity 10000
```

Добавь следующие секреты репозитория в настройках GitHub Actions:

| Секрет | Значение |
| --- | --- |
| `SIRIN_KEYSTORE_BASE64` | Файл хранилища ключей, закодированный в Base64 |
| `SIRIN_KEYSTORE_PASSWORD` | Пароль хранилища |
| `SIRIN_KEY_ALIAS` | Имя ключа в хранилище |
| `SIRIN_KEY_PASSWORD` | Пароль ключа |

Передать закодированный файл можно без вывода его содержимого в терминал:

```sh
base64 -w 0 /secure/path/sirin-release.jks | gh secret set SIRIN_KEYSTORE_BASE64
```

Для остальных трёх секретов используй интерактивный `gh secret set ИМЯ_СЕКРЕТА` или настройки секретов Actions в GitHub. Сценарий сборки восстанавливает хранилище во временном каталоге исполнителя и удаляет его, даже если сборка завершается ошибкой.

## Локальная сборка релиза

Укажи `SIRIN_KEYSTORE_PATH`, `SIRIN_KEYSTORE_PASSWORD`, `SIRIN_KEY_ALIAS` и `SIRIN_KEY_PASSWORD` в переменных окружения. Секреты не должны попадать в историю команд или отслеживаемые файлы.

```sh
export SIRIN_VERSION_NAME=2.0.0
# Укажи числовой SIRIN_VERSION_CODE выше последнего выпущенного.
./gradlew :app:testDebugUnitTest :app:lintRelease :app:assembleRelease
"$ANDROID_HOME/build-tools/37.0.0/apksigner" verify --verbose \
  app/build/outputs/apk/release/app-release.apk
```

Без переменных подписи локальный release APK остаётся неподписанным. Сценарий публикации проверяет наличие всех секретов и подпись готового APK перед загрузкой. Debug APK подписывается сертификатом разработки и не предназначен для релизов.

## Публикация

Когда изменения релиза проверены и закоммичены в `master`, создай и отправь подписанный тег версии:

```sh
git tag -s v2.0.0 -m 'Sirin Music 2.0.0'
git push origin master
git push origin v2.0.0
```

Сценарий берёт `versionName` из тега, а `versionCode` — из растущего номера запуска этого сценария в GitHub Actions. Если ранее распространялись APK, собранные вручную, перед публикацией обновления убедись, что получаемый код версии выше последнего выпущенного. Сохраняй историю номеров запусков для совместимости обновлений.

Обычный тег создаёт релиз. Тег предварительной версии, например `v2.0.0-rc.1`, создаёт предварительный релиз в GitHub. При ручном запуске указывается уже существующий тег версии. Повторный запуск заменяет вложенные APK и файл контрольных сумм.
